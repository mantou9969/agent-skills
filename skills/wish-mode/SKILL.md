# wish-mode（许愿式交付）

用户的原话是：**「不允许 AI 莫名其妙创建一大堆文件，这一辈子都看不完」「我要的是一步一步来的许愿式任务，给我一口气做完，完全放权 AI 的那种」「计划书最多生成 2 个文件」。**

这份技能就是对这三句话的执行细则。它约束的不是内容质量，是**产出形态**：**结果进对话，垃圾不进磁盘。**

---

## 铁律（违反任意一条即为失败）

1. **文件预算制**：任何任务开始前先定预算，默认 **0 个新文件**。计划书/方案/规划/调研/攻略类任务，**上限 2 个文件**（含任何 README、索引、总控、台账）。
2. **一口气做完**：不写计划等批准、不停下来问"要不要继续"、不产出中间草稿。直接做到能交付，最后一次汇报。
3. **结果进对话**：过程、判断、结论、风险、下一步——全部写在回复里。**回复本身才是交付物**，文件只是附件。
4. **能合就不分**：新增文件前必须先问自己"这段能不能写进已有的那个文件"。能，就不新建。
5. **不许版本号**：不存在 `-v2`、`-final`、`-修订版`、`_20261027`。要改就**原地改**那个文件。
6. **排查类脚本一律不进工作区**：查东西（扫日志、解压会话、翻目录、验证某个字符串在不在）时，脚本写进 `$env:TEMP` 下**同一个文件**，反复改它重跑，任务结束删掉。工作区里出现 `scan_*.py`、`diag_*.js`、`find_*.py`、`verify_*.py`、`timeline_*.py` 这类文件＝违规。**"换一个假设"不是新建一个文件的理由。**

---

## 开工前 30 秒：三行声明（写进回复，不写进文件）

在动手前，在回复里先写这三行，让用户当场能拦住你：

```
愿望复述：<一句话，40 字内>
文件预算：新增 N 个（N ≤ 2，默认 0）；分别是 <文件名 → 为什么不能合并>
完成判据：用户拿到 <什么> 就算完成
```

**预算超 2 就要当场解释**。解释不了就砍到 2。

---

## 文件预算表（照这个判，不要自己发明）

| 任务类型 | 上限 | 说明 |
|---|---|---|
| 问答、解释、诊断、审阅 | **0** | 答案就在回复里。不许"顺便整理成文档" |
| 调研、比价、可行性判断 | **1** | 一个文件装完所有章节 |
| 计划书 / 方案 / 规划 / 路线图 | **2** | 通常 1 个就够。第 2 个只能是"给人看的成品"，不能是"给自己看的中间物" |
| 执行类（要跑代码、要出数据） | 文档 **1** + 脚本 **≤3** | 脚本必须能被一条命令串起来跑完，不许一步一个脚本 |
| 用户明确说"多出几个文件" | 按他说的 | 只有此时可以突破 |

**不算预算的**：用户点名的唯一交付物（比如他要一个 zip、一个 xlsx、一个 mp4）。这仍然只能有一个。

## 绝对禁止清单（出现即视为失控）

- ❌ `01-`、`02-`、`03-` …… 编号系列文档。**一旦写到 03，说明前两个本该合并。**
- ❌ 自动生成 `README.md`、`00-说明书`、`索引`、`总控`、`台账`、`汇总表`、`检查表`、`模板`、`接口约定`、`专家分工表`。
- ❌ 给"还没做的事"先建文档（计划、SOP、检查清单、话术库、素材库、目录结构说明）。
- ❌ 同一内容多个版本并存。
- ❌ 为了显得专业而分文件（一个人看不完的交付＝没交付）。
- ❌ 用多个文件表达"我做了很多工作"。**工作量用结论说话，不用文件数说话。**
- ❌ **为"查一个问题"写多个脚本**。查证类任务的文件预算是 **0**：写一个临时脚本（放 `%TEMP%`）、改它重跑、答完删掉。一个假设失败就换个思路改同一个文件，不许 `scan_xhs.js` → `diag_sessions.js` → `scan_xhs.py` → `index_sessions.py` 这样一路加文件。

## 许愿式执行：全权模式下怎么跑

用户说"放权给你"时，**默认你有权做一切可逆的事**，包括上网查、跑脚本、装依赖、改文件、跑数据、生成素材。

**只有这三类才允许停下来问：**
1. **不可逆**：删他的东西、覆盖他没让我改的文件、提交/发布到外部平台。
2. **花钱**：任何付款、订阅、投流、买样品。
3. **需要他本人的身份或凭据**：登录、实名、人脸、验证码、签字。

其余一律**先做，做完再说**。不要问"需要我继续吗"——那是把决策成本丢回给用户。

**中途撞墙怎么办**（很常见，别因此退回写文档）：
- 失败一次 → 换一条路继续，记在回复里。
- 失败三次 → 在回复里写清楚"卡在哪、为什么、需要你做什么"，然后停。**不许为了绕开阻塞去写文档。**

---

## 收尾自检（交付前必过）

1. 我这次新增了几个文件？**> 2 就现在合并或删除。**
2. 如果只能留一个文件，是哪个？其余的能不能并进去？
3. 回复里有没有"详见文件"？有 → 把那句话的内容直接写进回复。
4. 回复本身能不能独立读懂？不能 → 补，而不是加文件。
5. 有没有出现编号系列、README、台账、模板？有 → 删。

---

## 汇报格式（固定，短）

```
做完了：<一句话结论>
依据：<2-4 条关键事实/数字>
文件：<0 个 或 具体路径>
没做到的：<如果有，写清为什么 + 需要用户做什么>
```

不要写"我为你准备了……"这类铺垫。用户要的是结果。

## 真实反例（这就是触发本技能的原因）

2026-10-27 那次"3 天熟悉电商"的任务，最终在工作区留下了 **17 个条目 / 20 多个文件、约 600 KB**：3 份总控计划、4 份 CMO 方案、10 个 AI 图像文档、6 份选题团文档、2 份验收报告、2 份终裁表、2 份同名不同内容的 `13-` 文件……
用户的原话是：「**这谁看得完啊**」。

**正确答案当时应该是 2 个文件**：
1. `选品结论.md` —— 40 个选品逐个的"做/不做 + 理由 + 反理由"，一个文件装完。
2. `三天怎么做.md` —— 每天上午/下午/晚上干什么，可直接照做。

其余全部内容（平台规则、取证台账、证据分级、脚本清单）都属于**回复内容**或**第 1 个文件的章节**，不该是独立文件。脚本另外放，因为它们要跑。

**记住这个教训：多产出的文件不是勤奋，是把阅读成本转嫁给用户。**

## 真实反例 2（2026-10-28，同一个错又犯了一次）

用户只问了一句「**你检查一下 deepseek 的对话，是哪个对话帮我创建了小红书商铺账号**」。
这是一次**纯查询**，预算是 **0 个文件**。结果在工作区 `05-scripts\` 里留下 **11 个脚本 + 2 个 JSON（约 135 KB）**：

`scan_xhs.js` → `diag_sessions.js` → `scan_xhs.py` → `index_sessions.py` → `find_xhs_action.py` → `list_session_titles.py` → `find_xhs_user_ask.py` → `dig_ark.py` → `timeline_xhs.py` → `verify_shop.py` → `timeline_shop.py`，外加 `sessions_index.json`、`sessions_action_index.json`。

**真正的原因，一句话说清**：我每换一个假设就新建一个脚本，而不是改同一个。
- 假设「按标题搜」→ 建 `list_session_titles.py`
- 假设「搜用户提问」→ 建 `find_xhs_user_ask.py`
- 假设「搜工具调用里的 URL」→ 建 `find_xhs_action.py`
- 假设「定位店铺名」→ 建 `verify_shop.py`
- 假设「排时间线」→ 建 `timeline_shop.py`
- 中间还因为 node 的 zstd 只解第一帧，废掉一个 `scan_xhs.js` 又重写 `scan_xhs.py`——**同一个功能写了两遍、两个文件**

用户的原话是：「**你为啥写了11个文件 我让你查询一下你写11个文件怎么想的 这是什么东西**」。

**正确答案**：一个 `%TEMP%\x.py`，改六次，跑六次，答完删掉。工作区 **0 个文件**。所有答案都在回复里——工作区、会话标题、会话 ID、店铺名「后现代马铃薯」、时间线、以及那句「恭喜您的店铺已开通」的页面原文。

**判据**：如果这次任务的产出是"一段能看懂的结论"，那它就不该有脚本文件的残留。**查证类任务留下脚本，等于把过程垃圾丢给用户。**
